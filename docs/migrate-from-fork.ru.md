# Перенос установки старого форка на этот форк

[English](migrate-from-fork.md) | Русский

**Одноразово.** Для тех, кто держит СТАРЫЙ форк (`origin/feat/fork-integration`,
коммит `040410ac`) и хочет перейти на этот форк с данными. Это не обновление
этого форка (для него `scripts/ops/deploy.sh`) и не перенос с других коммитов
старого форка.

Остаётся: пользователи, их ссылки подписки, ключи и `numeric_id`, сквады,
профили, привязки, хосты, каскады, настройки панели, пресеты, правила выдачи,
история трафика, учётная запись администратора с 2FA, токены API, доверие к
нодам (CA и сертификаты). Ноды остаются в панели; их агенты переустанавливаются
(ниже). Что не остаётся, названо в разделе «Что теряется».

## Перед началом

- Старая панель стоит **точно** на `040410ac`. Другой коммит: сначала обновите
  старый форк до `040410ac` его собственным деплоем. Предпроверка судит по базе
  (журнал из 65 миграций, схема равна схеме старого форка) и отказывает фразой,
  которая это говорит.
- Свободного места на томе Postgres не меньше двух размеров базы (копия) и
  место под резервные копии в `<панель>/backups`.
- Окно простоя панели (копия, 54 миграции, преобразования: от секунд до
  нескольких минут). Ноды держат прежнюю конфигурацию, пользователи не
  отключаются.
- `JWT_SECRET` в `.env.production` **не меняется**: им подписан вход и от него
  зависят входные ноды, выданные подписчикам.
- Прочтите «Что теряется», особенно про профили с пост-квантовыми полями
  REALITY или VLESS Encryption и `abusePolicy`.

## Порядок

На хосте панели, рядом со старой установкой (здесь `/opt/iceslab`):

```bash
git clone --branch omega https://github.com/alldevic/iceslab.git /opt/iceslab-new
cd /opt/iceslab-new
scripts/ops/migrate-from-fork.sh --check --panel-dir /opt/iceslab    # только читает, пишет отчёт
scripts/ops/migrate-from-fork.sh --run   --panel-dir /opt/iceslab    # перенос
```

(`--repo` и `--ref` задают, чем станут `origin` и ветка установки; по умолчанию
репозиторий этого форка и `omega`. Пункт меню: `scripts/iceslab.sh migrate-from-fork --check`.)

`--check` собирает образ этого форка, запускает в нём предпроверку и пишет
`<панель>/backups/fork-migration/pre-check-<время>.json` с полями `blocking`,
`warnings`, `info`. `--run` сначала делает то же и останавливается на любой
`blocking`. Дальше:

1. резервная копия старой базы (`iceslab-backup.sh`), старые образы получают тег `:pre-fork`;
2. останавливаются backend и frontend (Postgres и Redis остаются);
3. **на копии базы** (`<база>_migrating`): 7 миграций этого форка, чей эффект в
   старой базе уже есть, отмечаются применёнными, 15 имён только старого форка
   уходят из журнала, `prisma migrate deploy` применяет остальные 48 + 6,
   затем преобразования (ниже), затем сверка (схема равна схеме этого форка,
   журнал в точности этого форка, ни одна строка общих таблиц не потеряна,
   контрольные суммы секретов равны);
4. `TRUST_PROXY_HOPS` записывается в `.env.production` со значением, с которым
   работала старая панель (здесь по умолчанию 2, там было 1, а неверное число это
   ошибка безопасности), делается резервная копия копии;
5. Redis сбрасывается (только очереди и счётчики; ваших данных там нет);
6. базы переименовываются: старая остаётся как `<база>_pre_fork`; у каталога
   меняются `origin` и ветка, собираются образы, поднимается стек, ждётся `/health`.

Отчёт: `migrate-from-fork-<время>.json`. Затем сразу переустановите агент
**каждой ноды** (ниже).

## Что делают преобразования

| Шаг | Что |
|---|---|
| hardening-strip | снимает `zapret2`, `bridgeNonXrayInbounds`, `egressPolicy` из `nodes.hardening` (строгая схема этого форка иначе отвечает 400); значения идут в отчёт |
| egress-policies | политика выхода **ноды** становится политикой ноды `fork-<нода>`; политика **члена каскада** только если нода в ровно одной позиции и своей политики не имеет; правила, которые старый компилятор и так отбрасывал (zapret2, link-out у ноды, WARP без WARP), отбрасываются с причиной. Остальное целиком в `egress-policies-not-converted.json`: переносится руками |
| geo | источники со своими URL становятся url-наборами (`<имя>-site`, `<имя>-ip`); источник runetfreedom по умолчанию не переносится (его место у встроенных наборов); категории становятся составными наборами `geo-custom` (домены) и `geo-custom-ip` (адреса) с теми же именами в нижнем регистре; `ext:geo-custom.dat:X` в хранимых правилах становится `ext:geo-custom:x`. **На ноды ничего не раскатывается**: сделайте это на экране гео, когда наборы соберутся |
| profile-engine | `engine = 'mtproto'` (явный mtg) становится родным ядром: поведение то же |
| hwid-trim | user agent устройств длиннее 512 символов обрезается (число в отчёте) |
| wg-unique | `wg_devices.public_key` становится уникальным (повтор ключа это блокирующая находка) |
| drop-old-columns | уходят `nodes.egress_tune`, `port_hopping_start/_end`, `cascade_position_nodes.egress_policy`; их значения сначала в отчёт |
| srr-report | **ничего не меняет**: перечисляет правила выдачи, отличающиеся от свежей установки этого форка |

## Что теряется или меняется

| Что | Почему | Что делать |
|---|---|---|
| zapret2: `hardening.zapret2`, `/applyEgress`, самонастройка, `nodes.egress_tune` | не переносится по решению | значения в отчёте; почистить ноды (ниже) |
| Пост-квантовые поля REALITY / VLESS Encryption, `abusePolicy` профиля | отклонено по решению | **блокирует**: сначала перевыпустите профили, либо `--accept-loss` (и введите фразу): клиенты со ссылками на их основе перестанут подключаться |
| Политики выхода членов каскада | здесь одна политика на ноду | однозначные конвертируются, остальные в отчёте |
| Гео-источники и категории | другая подсистема (гео-наборы) | конвертируются; раскатка на ноды за вами |
| Диапазон port hopping у Hysteria | теперь его сообщает агент | вернётся после переустановки агента; до того подписка его не несёт |
| `pinnedPeerCertSha256` у профиля Hysteria | пин берётся из отчёта ноды | в находке `config-keys-dropped`; переустановите агент |
| Тело подписки | другие форматы и порядок (вехи 6.2, 6.4, 10.5, 12.x, 13.x) | ссылки `/sub/<token>` те же |
| Правила выдачи (User-Agent → формат) | остаются как есть | в отчёте отличия от свежей установки (Clash и NekoBox остаются на `clash`/`singbox` вместо `mihomo`, у WireGuard приоритет 60 вместо 65, нет правила `v2rayNG`, если v2rayN правили) |
| Redis: счётчики лимитов, блокировки входа, список ловушки | временное | нет |
| `hwid_user_devices.user_agent` длиннее 512 | тип столбца | обрезка |
| Таблицы `inbounds`, `group_inbounds` | давно мертвы | **блокирует**, если не пусты |

## Ноды

Агент старого форка говорит по другому договору (нет `/addUsers`, `/assets`,
`/connLog`, `/rotateCert` с одной стороны, `/applyEgress` и `/generateKeys` с
другой). **Совместимость новой панели со старым агентом не обещается**:
переустановите каждую ноду сразу после переноса. В панели: нода, «Refresh
bootstrap», выполнить показанную команду на ноде. Потом проверьте версию в
`/healthz`, пуш конфигурации и что port hopping вернулся в подписку.

Остатки zapret2 на ноде, которых перенос не касается (убирать руками, только
там, где он был включён):

```bash
cd /opt/ss-zapret2 && docker compose down; rm -rf /opt/ss-zapret2
systemctl disable --now iceslab-egress-selftune.timer
rm -f /etc/systemd/system/iceslab-egress-selftune.{service,timer} /usr/local/bin/iceslab-egress-selftune.sh
rm -f /etc/systemd/system/iceslab-node.service.d/zapret2-rw.conf /var/lib/iceslab-node/egress-tune.json
sed -i '/^ZAPRET2_/d' /etc/iceslab-node/env     # если установщик этого форка оставил
systemctl daemon-reload
```

## Возврат

```bash
cd /opt/iceslab-new
scripts/ops/migrate-from-fork.sh --rollback --panel-dir /opt/iceslab
```

База `<база>_pre_fork` возвращается на место, перенесённая сохраняется как
`<база>_migrated_<время>`, возвращаются `origin` и коммит старого каталога,
поднимаются образы с тегом `:pre-fork`. Всё, что изменилось в панели после
переноса, теряется. `--run` можно запустить снова позже. Старая база и образы
хранятся, пока вы их не удалите; делайте это, только когда уверены.

## Как читать находки предпроверки

`blocking` останавливает `--run`:

| код | смысл | выход |
|---|---|---|
| `not-old-fork-commit` | журнал не из 65 миграций `040410ac` | обновить старый форк до `040410ac` |
| `journal-unfinished` | миграция упала или откатана | разобрать в старом форке |
| `already-migrated` | в базе миграции этого форка | делать нечего |
| `schema-drift` | схема отличается от старого форка (правили руками?) | вернуть правку или спросить |
| `link-protocol-unknown` | `link_protocol` каскада, которого этот форк не читает | поправить ячейку в старой панели |
| `cascade-link-no-port` | у звена каскада нет порта | пересоздать звено |
| `binding-transport-unknown` | привязка профиля с неизвестным протоколом | убрать или поправить |
| `wg-key-repeated` | открытый ключ WireGuard у двух устройств | отозвать / перевыпустить |
| `dead-table-not-empty` | в `inbounds` / `group_inbounds` есть строки | посмотреть, что это, очистить таблицу |
| `lossy-profiles` | профили с полями, которые этот форк отбросил | перевыпустить или `--accept-loss` |
| `jwt-secret-missing` | нет `JWT_SECRET` | он должен быть в `.env.production` |

`warnings` и `info` не останавливают; читайте их. `stored-content-unreadable`
называет строки, которые схемы новой панели не примут.

## Не охвачено

Реальных данных оператора не было: перенос проверен на синтетической
установке, наполненной через API старой панели. Ручные правки базы сверх того,
что сравнивает предпроверка, необычные значения JSON, очень большие таблицы
истории (время копии, перезапись таблиц) и магазин `remnawave-minishop` не
проверялись. Состояние до переноса лежит в резервной копии, старой базе и
старых образах: храните их, пока новая панель не отработает какое-то время.
